表單處理與前端輸入驗證

03 · VALIDATION

驗證有兩層

HTML 先檢查

required、type="email"、minlength 可以提供基本格式限制和使用者提示。

JavaScript 補充規則

處理 trim 後的姓名長度、顯示欄位錯誤，以及表單成功後的畫面更新。

後端必須再驗證

使用者可以停用 JavaScript 或直接呼叫 API；真正儲存資料前，伺服器仍要檢查輸入。

form.addEventListener("submit", (event) => {
  event.preventDefault();
  // 讀取輸入 → 驗證 → 更新畫面
});

04 · XSS

把輸入當文字，不要當 HTML

不安全：innerHTML

result.innerHTML = username;

瀏覽器會把字串解析成 HTML；不可信內容可能被當成標記或程式處理。

安全顯示純文字：textContent

result.textContent = username;

輸入會以純文字顯示，不會被解析成 HTML。本練習使用這種方式。

可在姓名欄位測試像 <img src=x onerror=alert(1)> 這種字串； 安全的結果應該只是顯示字元，而不是執行任何內容。

05 · SECURITY RESPONSIBILITY

前端驗證是體驗，後端驗證是必要防線

本頁表單僅作為瀏覽器練習，不會將姓名、Email 或密碼傳送到伺服器。 真正的註冊功能需要後端再次驗證，並安全處理密碼；不能只相信瀏覽器送來的內容。

練習安全習慣

不要在公開網站或 GitHub 輸入、保存真實密碼或個人資料。也不要直接用 innerHTML 顯示未信任的使用者輸入。

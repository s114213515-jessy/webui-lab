WEB PROGRAMMING · WEEK 01

環境與 Git

先確認寫程式、執行程式和保存版本的工具各自負責什麼，再開始建立網站。

VS Code→ 專案資料夾→ Git→ GitHub

01 · LEARNING GOALS

完成本週後，你可以

  • 分辨編輯器、JavaScript 執行環境、版本控制和遠端儲存庫的工作。
  • 從 VS Code 終端機確認 Node.js、npm 和 Git 可以使用。
  • 用 Git 記錄修改，並理解本機 repository 和 GitHub repository 的差異。
  • 在專案開始時設定忽略規則，避免提交依賴套件或秘密設定。

02 · TOOL RESPONSIBILITIES

工具各自負責不同工作

工具用途要記住的差別
VS Code 編輯檔案、查看程式和使用終端機 它是編輯工具，不是 GitHub 或網站伺服器。
Node.js / npm 在瀏覽器以外執行 JavaScript，管理 JavaScript 套件與工具 瀏覽器本身也能執行前端 JavaScript；Node.js 讓開發工具能在本機執行。
Git 在本機追蹤檔案變更並建立版本 commit 先存在本機，不會自動出現在 GitHub。
GitHub 託管遠端 repository，分享程式和版本歷史 push 才會把本機提交同步到遠端。

03 · CHECK YOUR ENVIRONMENT

從終端機確認工具可用

node --version
npm --version
git --version

終端機若找不到指令，常見原因是程式未安裝，或執行檔路徑未加入 PATH。 Windows 使用者權限不足時，教材示範將 Node.js ZIP 解壓至個人目錄，再設定使用者 PATH； PATH 更新後通常要重新開啟 VS Code 才會套用。

遇到 PowerShell 的 npm 執行限制

本專案紀錄的做法是使用 npm.cmd，而不是為了方便就放寬整台電腦的執行原則。先看錯誤原因，再選擇影響範圍較小的處理方式。

04 · VERSION CONTROL

用 Git 忽略不該追蹤的檔案

.gitignore 用來指定 Git 不需要追蹤的檔案，例如套件資料夾、建置產物、 編輯器暫存檔和本機環境設定。密碼或 token 不應提交到 repository； 如果秘密已經提交，單純新增忽略規則並不會從既有 Git 歷史中移除它。 

git status
git add .
git commit -m "建立專案起始版本"
git push -u origin main

第一次推送使用 git push -u origin main，同時設定遠端追蹤分支； 後續才可直接使用 git push。commit 是本機版本紀錄，push 才是送到 GitHub 的步驟。

05 · CHECKPOINT

建立本機預覽並確認範圍

本專案的本機預覽綁定 127.0.0.1，表示只供目前這台電腦使用。 確認首頁能開啟後，再檢查 Git 狀態和提交紀錄。

  1. 確認三個版本指令都有回應。
  2. 確認專案有適合的 .gitignore，沒有加入秘密或個人資料。
  3. 用 git status 和 git log --oneline 檢查版本狀態。
  4. 分別確認本機預覽、Git commit 和 GitHub push 的作用。

WEB PROGRAMMING · WEEK 07

Fetch API：從資料到畫面

延續 W6，練習讓導覽和摘要卡片共用 API 資料，點擊後再載入詳細資料。

Event→ Function→ fetch()→ HTTP / JSON→ DOM

本專案使用 FastAPI 提供的虛構範例資料，不連接真實校務資料或外部服務。

01 · LEARNING GOALS

完成本週後，你可以

  • 解釋使用者點擊如何一路觸發 Fetch，最後更新網頁內容。
  • 從 API 的 JSON 摘要建立導覽項目和儀表板卡片。
  • 點選分類後取得詳細資料，並用 DOM 顯示欄位。
  • 使用 Network、Console 和 HTTP status 檢查錯誤，不把失敗當成空資料。

const response = await fetch("api/root");
if (!response.ok) {
  throw new Error(`HTTP ${response.status}`);
}
const categories = await response.json();
renderCategories(categories);

`await` 讓程式等候請求結果；`response.ok` 檢查 HTTP 狀態； `response.json()` 把回應內容解析成 JavaScript 資料。

03 · API SHAPE

摘要和詳細資料分開取得

用途請求回傳資料
建立固定導覽與摘要卡片 GET api/root cid、name、n
點擊分類後讀取詳細資料 GET api/root/co/{cid} 該分類中的範例物件陣列
為什麼要共用同一份摘要資料？

同一份 `/api/root` 回應會用來建立側邊導覽和摘要卡片，避免兩邊各自維護資料而顯示不一致。選取項目的詳細資料則按需要再取得。

04 · TRY IT

動手操作

  1. 回到儀表板，觀察系所、學期、課程等摘要卡片和側邊導覽。
  2. 點摘要卡片的「查看詳情」，再點側邊導覽中的其他分類。
  3. 開啟瀏覽器開發者工具的 Network，確認先載入 api/root，點擊後載入 api/root/co/分類編號。
  4. 檢查回應 JSON 的欄位，並確認頁面只顯示前四個欄位。

回到儀表板操作

Event → Function → fetch() → HTTP/API → JSON → DOM

每次操作都試著說出這六個步驟。若畫面沒有更新，先找出流程停在哪一步。

05 · DEBUGGING

出錯時依序檢查

  1. Network 有沒有送出請求？URL 和分類編號正確嗎？
  2. HTTP status 是成功、404，還是連線錯誤？
  3. 回應能否解析成 JSON？資料欄位是否符合預期？
  4. 事件有沒有呼叫正確的 function？render 是否更新 DOM？
  5. 資料放進畫面時是否以純文字方式處理？
